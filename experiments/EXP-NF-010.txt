HYPOTHESIS
The Solidity Merkle implementation associates historical roots with
their originating tree number and rejects a root when queried under
a different tree number.

TEST
A local Hardhat runtime test deployed MerkleRootHistoryHarness and
RuntimeMockPoseidon. The harness inherited the target repository's
Merkle implementation.

Tree depth: 2
Inserted leaves: 101, 102, 103, followed by 104.
The first three leaves filled tree 0 and the fourth insertion caused
rollover to tree 1.

ASSERTIONS
isValidRoot(0, tree0Root) == true

RESULT
PASS. The tested Solidity Merkle implementation accepted each root
under its originating tree number and rejected it under the other
tree number after rollover.

LIMITATIONS
RuntimeMockPoseidon uses keccak256 modulo the BN254 scalar field.
It is a deterministic test double, not the production Poseidon
permutation. This experiment establishes tree-index isolation in
the inherited Merkle implementation; it does not establish
cryptographic equivalence to production Poseidon.
